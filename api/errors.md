# Error handling

Every error response has the same shape, regardless of which service handled the request:

```json
{ "error_code": "invalid_api_key", "message": "the api key is invalid or revoked" }
```

The HTTP status carries the category; `error_code` is the stable, public identifier to
branch your code on — `message` is for humans and may change wording over time.

This table is generated by hand from `libs/core/errors` and each service's own error
values today — see the note on that package: *"One failure must not return 500 in one
service and 422 in another, so every error maps to an HTTP status ... at the same time."*
If you see an `error_code` in a response that isn't listed here, treat the HTTP status as
authoritative and [let us know](mailto:support@keenvector.in).

## Common errors

| HTTP | `error_code` | Meaning | Where |
|---|---|---|---|
| 400 | `invalid_request` | A field failed validation. `message` names the field. | Any endpoint |
| 401 | `missing_api_key` | No `Authorization` header on the request. | `/v1/messages` |
| 401 | `invalid_api_key` | The key doesn't exist, or has been revoked. | `/v1/messages` |
| 409 | `whatsapp_not_connected` | No WhatsApp Business Account connected for this tenant yet — connect one first. | `/whatsapp/messages`, `/whatsapp/messages/template`, `/whatsapp/templates` |
| 502 | `send_failed` | KeenVector reached the provider and it rejected the request outright — not the same as a `FAILED` status on an otherwise-accepted message. | `/v1/messages` |
| 502 | `provider_error` | Generic upstream provider failure. | WhatsApp-backed endpoints |
| 404 | *(none — plain text body)* | The resource doesn't exist for your tenant. | `/campaigns/{id}`, webhook config lookups |

## Retry guidance

- **4xx (except 429, not yet in use — see [Rate limits](/api/rate-limits))**: don't retry
  without changing the request. The request itself is wrong.
- **502 `send_failed` / `provider_error`**: safe to retry a *new* attempt, but reuse the same
  [`Idempotency-Key`](/api/messages#idempotency-key-header) if you're retrying the exact same
  send — otherwise you risk a duplicate.
- **5xx with no `error_code`** (an unhandled server error): safe to retry with backoff.

## A `201`/`202` is not a delivery guarantee

`POST /v1/messages` returning `201` means KeenVector accepted and forwarded your request —
check the `Status` field (`SENT`/`FAILED`) on the response, and subscribe to
[Webhooks](/api/webhooks) for the actual delivered/read outcome. A queue-backed accept
(`202`, used by outbound-webhooks) means the same thing one layer further out.
